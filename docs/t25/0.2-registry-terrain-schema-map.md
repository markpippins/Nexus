# 0.2 — Registry ↔ Terrain Schema Map (T25 Phase 0 Recon)

Two Spring services hold overlapping "topology" concepts on different ports:
service-registry (**:8085**, catalog/registration) and terrain (**:8084**,
runtime provisioning/topology). Both paginate as
`{ data: [], meta: { page, per_page, total, last_page } }` (0-indexed `page`,
fixed `per_page=20`).

## Service registry (:8085) — "what is registered / desired"

| entity | endpoint | key fields |
|---|---|---|
| ServiceInstance | `/api/v1/services` | id, name, description, `framework{nested}`, `type{nested}`, apiBasePath, status(`ACTIVE`…), activeFlag, healthCheckPath, frameworkId, serviceTypeId |
| Server | `/api/v1/servers` | id, hostname, ipAddress, cpuCores, memory, disk, `type/env/os{nested FK}`, region |
| Framework | `/api/v1/frameworks` | id, name, description, `category{nested}`, `language{nested}`, currentVersion/ltsVersion/latestVersion, url |
| Library | `/api/v1/libraries` | id, name, description, `category{nested}`, `language{nested}`, currentVersion, packageName, packageManager |
| Deployment | `/api/v1/deployments` | id, `service{nested}`, status, healthStatus |
| DomainSystem | `/api/v1/registry/systems` (raw array) | id, name, description, `systemType{nested}`, activeFlag |
| Status | `/api/v1/status` | serviceId, serviceName, healthState, lastHeartbeat, published |
| Lookups | `/api/v1/{service-types,server-types,environments,operating-systems,framework-categories,framework-languages,library-categories,framework-vendors}` | id, name, description, activeFlag |
| Registration | `/api/v1/registry/{register,heartbeat/:name,heartbeat/batch,deregister/:name(/graceful)}` | — |
| Aggregate/logs/metrics | `/api/v1/registry/{aggregate,logs/:type/:id,metrics/:type/:id}` | — |

## Terrain (:8084) — "what is provisioned / running"

| entity | endpoint | key fields |
|---|---|---|
| Server | `/api/v1/servers` | id, hostname, ipAddress, os, status, activeFlag, startup, startupScript, buildCommand, health, **sysUser, sysPass**, notes, isInternal |
| RunnableService | `/api/v1/runnable-services` | id, name, port, workspacePath, serviceTypeId, healthCheckUrl, status, version, description, repositoryUrl, activeFlag, startup, startupScript, buildCommand, health (68 rows) |
| McpServer | `/api/v1/mcp-servers` | id, name, port, workspacePath, serviceTypeId, healthCheckUrl, status, transportType, version, description, repositoryUrl, … (14 rows) |
| ServiceDependency | `/api/v1/service-dependencies` | id, sourceType, sourceId, targetType, targetId, criticality, description (19 rows) |
| BrokerProfile | `/api/v1/broker-profiles` | id, profileId, name, brokerUrl, imageUrl, autoConnect, healthCheckDelayMinutes |
| PlatformHealth | `/api/v1/platform/health` | timestamp, mcpServers, runnableServices, hostServers, terrainUp |
| Also | `/api/v1/cli-tools`, `/api/v1/registry-server-profiles`, `/api/v1/service-types` | — |

## Overlap / collision

| concept | registry (:8085) | terrain (:8084) |
|---|---|---|
| **servers** | catalog Server (spec: cpu/mem/disk, nested type/env/os FK) | host Server (provisioning: os, startup, **sysUser/sysPass**) |
| service-types | lookup table | lookup table |
| service-dependencies | dependency graph | `{sourceType,sourceId,targetType,targetId}` graph |
| services | `ServiceInstance` (catalog, 69) | `RunnableService` (runtime, 68) — near 1:1 count, different fields |

## Key divergence

- Registry = catalog/registration truth; Terrain = provisioning/runtime truth.
  The **Server** entity is the biggest semantic split (provisioning creds vs.
  catalog spec).
- `sysUser`/`sysPass` on terrain servers is a credential-in-schema smell (see 2.3).
