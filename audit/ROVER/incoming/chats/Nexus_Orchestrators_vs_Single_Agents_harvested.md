## 1. Structurally Sound Metadata Capture — Semantic Description, Not Metadata Entry
**Status:** `Agreed`

### Architectural Intent
Evolve from 'metadata entry' (manual data entry around code — Confluence, Jira, structured commits) to 'semantic description' (capturing intent, constraints, and relationships as first-class structured data). The goal is to reduce the 25-30% of developer effort spent on metadata work by making context implicit, generated, or pre-linked. TypeSpec becomes the language for semantic description — describing what the system means, not just what the code does. This is the shift from 'data-entry around the code' to 'structurally sound metadata capture using a semantic modeling language'.

### Requirements & Acceptance Criteria
- [ ] Shift from metadata entry to semantic description
- [ ] TypeSpec as semantic modeling language for system meaning
- [ ] Context becomes implicit, generated, or pre-linked
- [ ] 25-30% developer effort recovered from metadata work
- [ ] Business rules captured in TypeSpec contracts, not prose
