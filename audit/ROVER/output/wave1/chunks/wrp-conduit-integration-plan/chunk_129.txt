ScopeThis document defines how the initial WRP artifact set is ingested into Nebula:- `docs/wrp/wrp-v1-protocol.md`- `docs/wrp/wrp-v1_1-dag-model-and-compilation-pipeline.md`- `docs/wrp/wrp-v1_2-execution-traversal-engine.md`- `docs/wrp/wrp-migration-plan.md`The projection pipeline transforms those markdown documents into:- `NebulaArtifact` records- `NebulaSection` records- `NebulaChunk` records- `NebulaCrossReference` records- optional execution links to Conduit plans and receiptsThis document governs **projection behavior**, not authoring style. Projection ObjectivesThe projection pipeline MUST produce a graph that supports:1. **role-shaped retrieval**- Builder sees implementation-oriented chunks- Architect sees subsystem and rationale chunks- Inspector sees invariants, migration rules, and protocol constraints- Explorer sees rationale, open questions, and broader cross-artifact context2. **artifact-level identity**- each WRP document projects to a stable `NebulaArtifact`- each section and chunk receives stable identifiers3. **chunk-level stratification**- level assignment is done at chunk level, not only document level- a single document may yield L1, L2, and L3 chunks4. **cross-reference graph construction**- explicit and inferred relationships between chunks, sections, and artifacts are materialized into Nebula edges5. **Conduit interoperability**- artifacts and chunks may link to Conduit plans, execution receipts, or migration records where applicable---# 3. Projection Pipeline OverviewProjection MUST proceed in the following stages:1. **Artifact Resolution**- map source markdown file to known `NebulaArtifact`- create artifact if missing and bootstrap mode permits creation2. **Markdown Parsing**- parse headings, lists, paragraphs, tables, fenced code blocks, block quotes3. **Section Construction**- create ordered `NebulaSection` records from heading hierarchy4. **Chunk Segmentation**- split section bodies into semantically coherent `NebulaChunk` units5. **Chunk Classification**- assign:- `level`- `chunkKind`- `normativeStrength`- `status`- optional tags / concepts6. **Cross-Reference Extraction**- emit explicit and inferred edges among artifacts, sections, and chunks7. **Execution Link Attachment**- attach Conduit plan or receipt links where metadata exists8. **Persistence / Upsert**- write artifact/section/chunk/xref records using stable ids and idempotent upsert semantics---# 4. Chunk Segmentation RulesSections are often too coarse to retrieve effectively. Each section MUST be segmented into one or more `NebulaChunk` units.## 6.1 Chunking principleA chunk MUST represent **one dominant semantic purpose**.Do not mix the following in a single chunk unless they are inseparable and short:- protocol rule + migration checklist- rationale + normative invariant- algorithm + historical commentary- open question + implementation task list## 6.2 Primary chunk boundariesWithin a section, start a new chunk when any of the following occurs:1. **normative mode switch**- descriptive exposition changes into explicit requirements- requirements change into rationale or migration guidance2. **semantic subtype switch**- protocol semantics → data model- data model → algorithm- rationale → open questions- migration steps → compatibility constraints3. **structural block boundary**- fenced code block introducing a new implementation concern- numbered migration checklist- table encoding a model or mapping- quoted rule / invariant block4. **topic pivot**- paragraph group changes subject materially even within same heading## 6.3 Secondary chunk boundariesThe projector SHOULD split large chunks when:- chunk text exceeds configured token threshold- chunk contains more than one independent invariant- chunk contains more than one migration step cluster- chunk interleaves prose and code examples in a way that harms retrieval specificity## 6.4 Default chunk size guidanceTarget chunk size:- **preferred:** 150–450 tokens- **acceptable:** 80–700 tokensThe projector SHOULD avoid:- micro-chunks that contain only one sentence unless it is a high-value invariant- mega-chunks that contain an entire section with mixed concerns---# 7.
