use.This effective state may be materialized directly on the object row or computed from annotations.## 8.2 Default precedence ruleIf multiple annotations exist for the same object, the effective review state SHOULD be determined by:1. most recent human-authored authoritative annotation2. otherwise most recent approved role recommendation3. otherwise importer-initialized default4. otherwise `UNREVIEWED`## 8.3 Status severity tie-breakIf multiple candidate annotations are equally authoritative and recent enough to conflict, use the following severity ordering to avoid false optimism:- `CURRENT_FOCUS`- `UNDER_REVIEW`- `QUESTIONED`- `OUTDATED`- `NEEDS_REVIEW`- `REVIEWED`- `UNREVIEWED`- `SUPERSEDED_CONFIRMED`This severity ordering is for tie-breaking only and MUST NOT be interpreted as a universal ranking of importance.## 8.4 Why `SUPERSEDED_CONFIRMED` is not treated as “most severe”Superseded material is often safe to ignore rather than urgent to fix. It is not necessarily a live problem. Therefore it should not outrank `QUESTIONED` or `CURRENT_FOCUS` in attention logic.---# 9. Artifact / Section / Chunk Rollup RulesReview state may exist at multiple scopes simultaneously. The workflow needs rules for how lower-level review state influences higher-level summaries.## 9.1 Artifact effective review is primaryArtifact review status is the main corpus-level triage signal and SHOULD be set explicitly rather than inferred whenever possible.## 9.2 Section and chunk review do not automatically overwrite artifact reviewIf an artifact is marked `REVIEWED` but one chunk is marked `QUESTIONED`, the artifact does not automatically become `QUESTIONED`.Instead, the artifact SHOULD receive one or more rollup indicators such as:- `needsAttention = true`- `attentionReason += NEEDS_CHUNKING_REVIEW`- optional `focusScore` boost- optional “contains questioned chunk” derived flag## 9.3 Optional artifact rollup policyImplementations MAY define a rollup threshold such as:- if ≥ 30% of chunks are `OUTDATED` or `QUESTIONED`, artifact effective review becomes `NEEDS_REVIEW`- if any chunk is `CURRENT_FOCUS`, artifact `focusScore` is boosted- if all chunks are `SUPERSEDED_CONFIRMED`, artifact may be proposed as `SUPERSEDED_CONFIRMED`But this rollup SHOULD be advisory until chunk review is common enough to trust statistically.---# 10. Review ActionsThe review workflow recognizes the following actions.## 10.1 Mark Needs ReviewSet:- `reviewStatus = NEEDS_REVIEW`- optionally priority and attention reasonsUse when an item should enter the review queue.## 10.2 Start ReviewSet:- `reviewStatus = UNDER_REVIEW`Use when active review or rewrite has begun.## 10.3 Mark ReviewedSet:- `reviewStatus = REVIEWED`- `lastReviewedAt`- optional summaryUse when the item is current enough for normal use.## 10.4 Mark Current FocusSet:- `reviewStatus = CURRENT_FOCUS`Use when the item is a live center of implementation or architecture work.## 10.5 Mark OutdatedSet:- `reviewStatus = OUTDATED`Use when the item is no longer a safe default but may still be historically useful.## 10.6 Mark QuestionedSet:- `reviewStatus = QUESTIONED`Use when the item may be wrong, not merely old.## 10.7 Confirm SupersededSet:- `reviewStatus = SUPERSEDED_CONFIRMED`- set `supersededBy` if knownUse when a replacement is clear and the old material should be demoted from normal retrieval.---# 11. Relationship Between Supersession and ReviewSupersession and review are related but distinct.## 11.1 Supersession is a semantic relationshipExample:- `wrp-v1-protocol-v0` is superseded by `wrp-v1-protocol`This is modeled as:- `supersededBy`- `supersedes`- lifecycle `status`## 11.2 Review supersession is an operational confirmationAn item becomes `SUPERSEDED_CONFIRMED` when the team has decided it should be treated as superseded for retrieval and attention purposes.## 11.3 Auto-promotion ruleIf `supersededBy` is set, the system MAY propose:- `reviewStatus = SUPERSEDED_CONFIRMED`but SHOULD NOT automatically finalize it unless configured to do so.Reason:- some superseded artifacts still matter during a migration period- some artifacts are partially superseded but still operationally relevant---# 12. Review Workflow for Corpus TriageThis section defines the simple human workflow the system is meant to support.## 12.1 Initial triage passAs you review the corpus, each artifact SHOULD be assigned one of:- `CURRENT_FOCUS`- `NEEDS_REVIEW`- `REVIEWED`- `OUTDATED`- `QUESTIONED`- `SUPERSEDED_CONFIRMED`with optional:- priority- attention reasons- short review summaryThe goal is not perfection. The goal is to make the corpus sortable and navigable.## 12.2 Triage heuristics### Mark `CURRENT_FOCUS` when:- active implementation or redesign is centered on the artifact now### Mark `NEEDS_REVIEW` when:- the artifact is probably important but confidence is not high enough- the artifact predates a major design change- the artifact is about to become implementation-relevant again### Mark `REVIEWED` when:- the artifact is current enough to be used normally### Mark `OUTDATED` when:- the artifact still has historical value but should not be trusted as a default guide### Mark `QUESTIONED` when:- the artifact may encode wrong assumptions or contradictions### Mark `SUPERSEDED_CONFIRMED` when:- a replacement exists and default retrieval should normally prefer the replacement---# 13. Retrieval EffectsReview state MUST influence Nebula retrieval.## 13.1 Default retrieval behaviorUnless explicitly overridden:- `CURRENT_FOCUS` receives a strong ranking boost- `REVIEWED` receives a positive ranking boost- `NEEDS_REVIEW` remains retrievable but slightly demoted relative to reviewed/current material- `OUTDATED` is demoted- `QUESTIONED` is demoted for Builder/Architect defaults but may be boosted for Inspector- `SUPERSEDED_CONFIRMED` is excluded or strongly demoted from default retrieval## 13.2 Role-specific review-state behavior### BuilderPrefer:- `CURRENT_FOCUS`- `REVIEWED`Demote:- `OUTDATED`- `QUESTIONED`Exclude by default:- `SUPERSEDED_CONFIRMED`### ArchitectPrefer:- `CURRENT_FOCUS`- `REVIEWED`Allow:- `QUESTIONED`- selected `OUTDATED` material when rationale still matters### InspectorPrefer:- `QUESTIONED`- `NEEDS_REVIEW`- `OUTDATED`because those often indicate the places where validation and contradiction analysis are most needed.### ExplorerAllow broad inclusion, including:- `OUTDATED`- `SUPERSEDED_CONFIRMED`when historical lineage or unresolved questions matter.---# 14.
