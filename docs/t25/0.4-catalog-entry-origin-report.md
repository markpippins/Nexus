# 0.4 — Catalog-Entry Origin Report (seed vs registration)

## Seed (declarative, committed)

- `config/DataInitializer.java` + `config/VisualComponentSeeder.java`
- `resources/data-seed.sql` + `resources/db/migration/V1..V9`
- `resources/config/*.json`: frameworks, libraries, hosts, deployments,
  service-configurations, operating-systems, environment-types, host-types,
  framework-types, library-types.
- `NebulaSeedController` (`/api/v1/seed`) — on-demand reseed.

## Registration (runtime, via API)

- `POST /api/v1/registry/register` → `ExternalServiceRegistrationService`.
- Observed runtime-registered entries in the catalog: `image-server`,
  `file-system-server`, `secure-file-system-server`, `conduit-ui-legacy`, etc.
  (their `description` reads "External service registered via API").

## Key finding

The service catalog mixes seeded and runtime-registered entries with **no
persistent `origin` marker column**. If provenance is required for the 1.2
seed/sync work, add an `origin` (seed | register) / provenance column; today  origin is only inferable from `description` text and the seed JSON files.
