Projection ModelThis section defines how WRP material moves from authored docs / Conduit plans into Nebula entities.22. Projection SourcesA WRP artifact may enter Nebula from one of three sources.Source A — Markdown-authored specThe preferred source. A curated markdown spec exists under the repo and is imported into Nebula.Source B — Conduit plan projectionA Conduit plan or work packet is projected into Nebula as a lightweight execution-facing document when no richer Nebula document exists yet.Source C — Manual or generated synthesisA generated or manually synthesized architecture note is imported and later normalized.The preferred order is:Markdown specGenerated synthesisConduit projection fallback23. Projection Pipeline StagesEvery WRP artifact projection follows the same high-level pipeline.Source artifact→ artifact registration→ document ingestion→ section extraction→ chunk creation→ level assignment→ cross-reference extraction→ Conduit link registration→ optional open-question extraction24. Stage 1 — Artifact RegistrationInput:artifact keyartifact typeversionsource path or source identifierOutput:canonical artifact registration recordlink to the current Nebula document versionRules:artifact keys must be stable;new versions should supersede, not overwrite, old document rows;the current version should be discoverable by artifact key.25. Stage 2 — Document IngestionThe source markdown/spec is stored as a Nebula document.Required metadata:artifact_typeartifact_keyartifact_versionsource_kindstatusdefaultlevelDocument title should remain human-readable, e.g.:WRP v1.0 Protocol FormalizationWRP v1.1 DAG Data Model and Compilation PipelineWRP v1.2 Execution Traversal EngineWRP Migration Plan26.
