## 1. EA Tools as PowerPoint with Data Flow — Nexus as Code-Native Architecture
**Status:** `Agreed`

### Architectural Intent
Traditional EA tools (Archi, ArchiMate, Ardoq, Orbus, Enterprise Architect) are essentially structured slide decks with connectors — document-first, not code-first. They map and visualize enterprise architecture for multi-stakeholder visibility, compliance, and governance. Nexus takes the inverse approach: architecture lives in code, diagrams are optional outputs, and the system is executable rather than documented. Nexus is a 'small sharp tool' with high leverage ratio — easy to use, cheap to run. TypeSpec adds the microscopic precision EA tools missed: formalized, machine-verifiable contracts.

### Requirements & Acceptance Criteria
- [ ] EA tools = document-first, code-second architecture modeling
- [ ] Nexus = code-native, live, executable architecture
- [ ] Diagrams are optional outputs, not primary artifacts
- [ ] Nexus: small footprint, high leverage ratio
- [ ] TypeSpec: machine-verifiable contracts vs manual EA governance
- [ ] EA tools as 'Google Earth for architecture' — reference, not implementation

## 2. Power vs Leverage — Traditional EA vs Code-Native Architecture
**Status:** `Agreed`

### Architectural Intent
Traditional EA tools occupy the high-effort, moderate-leverage quadrant — full suite of governance, reporting, and diagramming overhead designed for bureaucratic leverage, not technical leverage. Nexus/Alloy.js/TypeSpec sits in the low-effort, high-leverage zone: small, sharp, precise tools that formalize, validate, and generate artifacts automatically. The missing plot EA tools missed by millimeters is that architecture should be live, codified, and type-checked, not just drawn.

### Requirements & Acceptance Criteria
- [ ] EA: high effort, moderate leverage — bureaucratic overhead
- [ ] Nexus: low effort, high leverage — executable architecture
- [ ] Code-native > document-first for system evolution
- [ ] TypeSpec: formalize, validate, generate — replace manual governance
- [ ] Live architecture > static diagrams
