- “Builder should mostly see implementation detail”
“Builder should mostly see implementation detail”

- Nebula retrieval
Nebula retrieval

context expansion limits

- weighting of normative vs descriptive chunks
weighting of normative vs descriptive chunks

# The core shape I think is right here

There arethree things in this schemathat I think are exactly the right axis for your system.

---

# 1)allowedLevelas a hard filter, not just a score hint

This is important.

For example,Builderis defined as:

- L1
L1

- L2
L2

not “prefer L1/L2 but maybe let L3 flood in if embeddings happen to like it.”

That means your retrieval pipeline can do:

## phase 1

retrieve candidate chunks by lexical / embedding relevance

## phase 2

hard filterto allowed levels for the active profile

## phase 3

apply ranking boosts for:

- preferred chunk kinds
preferred chunk kinds

- normative strength
normative strength

- active artifacts
active artifacts

- execution recency if allowed
execution recency if allowed

That preserves the whole point of stratification.

---

# 2)preferChunkLevelOverDocumentLevel

This looks minor, but I think it matters a lot.

You explicitly want documents like the WRP migration plan to contain:

- L3migration rationale
L3migration rationale

- L2compatibility rules
L2compatibility rules

- L1concrete migration tasks
L1concrete migration tasks

If retrieval only respected document-level classification, you’d lose that nuance. So the retrieval profile making this explicit is good: it tells the retrieval engine to trustchunk-level overridesas the primary abstraction signal.

---

# 3)includeExecutionLinksas a role-level toggle

This is a very good dividing line between Nebula-as-knowledge and Conduit-as-execution.

For example:

- Buildershould usually see execution links because “what plan is implementing this?” is relevant.
Buildershould usually see execution links because “what plan is implementing this?” is relevant.

- Inspectoroften should too, because “what actually got run / what receipt exists?” matters.
Inspectoroften should too, because “what actually got run / what receipt exists?” matters.

- Architectusually doesn’t need that in default retrieval.
Architectusually doesn’t need that in default retrieval.

- Explorerprobably doesn’t either.
Explorerprobably doesn’t either.

That’s exactly the kind of separation that stops every role from dragging execution metadata into every context window.
