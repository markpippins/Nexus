# What this schema is doing conceptually

It gives Nebula areview overlaythat isindependent of lifecycle status.

That means an artifact can simultaneously be:

- status = nebula:ACTIVE
status = nebula:ACTIVE

- reviewStatus = review:NEEDS_REVIEW
reviewStatus = review:NEEDS_REVIEW

or:

- status = nebula:SUPERSEDED
status = nebula:SUPERSEDED

- reviewStatus = review:SUPERSEDED_CONFIRMED
reviewStatus = review:SUPERSEDED_CONFIRMED

Those are not redundant; they answer different questions:

- status→ what is this artifact in the corpus lifecycle?
status→ what is this artifact in the corpus lifecycle?

- reviewStatus→ what attention should we pay to it right now?
reviewStatus→ what attention should we pay to it right now?

That split is the core reason to do this as a separate schema instead of just stuffing more enum values intostatus.
