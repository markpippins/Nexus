## Server-side (registry :8085)

- `RegistryController` + `ExternalServiceRegistrationService` serve:
  `POST /api/v1/registry/register`, `/heartbeat/:name`, `/heartbeat/batch`,
  `/deregister/:name`, `/deregister/:name/graceful`.
- Status tracking: `ServiceStatusController` (`GET /api/v1/status`),
  `ServiceStatusScheduler`, `ServiceStatusCacheService`,
  `DeploymentHealthScheduler`, and the `status_events` table (migration `V7`).
- Health streaming: `SseEmitterRegistry` + `RedisSseBridge`
  (`GET /api/v1/registry/stream`, `/stream/clients`).
- Heartbeat DTO: `HeartbeatPayload` (shared `service-registry-api` module).

## Staleness handling

- `status_events` records transitions; the status view exposes `lastHeartbeat`.
- The precise staleness/eviction threshold lives in `ServiceStatusScheduler`
  (confirm the TTL when documenting the canonical SLA).

## Gaps

- Auto-registration is implemented **only in the Java/Quarkus/Helidon broker
  stack + moleculer-search**. The Node/Python service fleet (nebula, conduit,
  knowledge, peb, semantics, cascade, …) does **not** self-register — they are
  either absent from the catalog or entered via seed/manual registration.
